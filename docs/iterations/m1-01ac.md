## Problem and actual code changes
A single A/B run in Chromium SwiftShader had large variability in P95 (for example prior radius42 vs35 overview light +94.65% in one run), so picking a culling variant from one pair is unreliable.

- `scripts/m1-near-ab-benchmark.mjs`: light **ABBA**, balanced **BAAB**, two matched repeats of control and candidate for each mode, repeat-indexed screenshot filenames and sample rows, explicit `runOrder`, metadata for the pairing method.
- `scripts/m1-ab-statistics.mjs`: pure paired-delta summarizer; per-pair calls/triangles/P95 deltas, median and min/max spread, frame counts, reject missing/duplicate/invalid/nonfinite/zero measurements, reject <5 frames. Does **not** pool frame-interval percentiles.
- `scripts/m1-ab-statistics.test.mjs`: seven deterministic Node tests for the invariants.
- `.github/workflows/m1-near-ab.yml`, `.github/workflows/m1-radius-ab.yml`: trigger on helper/script changes, run syntax and statistic tests, timeout 50m to allow 16 measured modes (2 variants × 2 qualities × 2 modes × 2 repeats) and 16 PNGs per workflow.
- `.github/workflows/ci.yml`: syntax-check A/B benchmark and helper, run 7 new statistics tests before production build.
- `docs/next-step-prompt.md`: focus on exact-SHA CI, A/B artifacts and honest follow-up.
